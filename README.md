# БУЛЬДОГ KURS

Проект подготовлен для размещения на BeGet.

## Структура

- `public_html/` — публичный сайт. Внутри только файлы, без вложенных папок.
- `secret/` — закрытые конфигурации, ключи и локальная база заказов. Содержимое не попадает в Git и не публикуется через веб-сервер.

Стартовая страница — `index.html`. Политика конфиденциальности и оферта находятся рядом с ней. Все изображения, документы, стили и скрипты используют плоские относительные пути.

## Заказы

Форма получает серверный расчёт доставки через `public_html/delivery.php`, а затем отправляет заказ в `public_html/order.php`. Сервер сам назначает номер, фиксирует статус `Новый`, товар, SKU, тариф СДЭК, ПВЗ или курьерский адрес, стоимость доставки и итоговую сумму и сохраняет заказ в основной базе MySQL. Только после этого заказ дублируется на лист `Заказы` в Google Sheets через Apps Script и отправляется в Telegram.

Расчёт использует API СДЭК и параметры коробки из закрытой конфигурации. Для ПВЗ выбирается ближайший доступный пункт к введённому адресу; для курьера рассчитывается доставка до двери. Страхование и остальные возвращённые СДЭК расходы входят в единую стоимость доставки и прибавляются к сумме заказа. Котировка подписывается случайным серверным токеном, действует 30 минут и не может быть подменена клиентом.

Код создания отправления реализован в `public_html/cdek-lib.php`, но реальный `POST /orders` заблокирован параметром `cdek.create_shipments = false`. Включать его можно только после отдельного тестирования боевого оформления.

## Обмен с 1С

Сервер поддерживает открытый протокол обмена 1С с сайтом и CommerceML 2 через адрес:

`https://origate-tactic.ru/1c_exchange.php`

Реализованы режимы:

- `catalog/checkauth`, `catalog/init`, `catalog/file`, `catalog/import` — авторизация, приём XML частями, сопоставление номенклатуры по артикулу/SKU и обновление остатка;
- `sale/checkauth`, `sale/init`, `sale/query`, `sale/success` — подготовка заказов сайта для 1С и подтверждение принятого пакета;
- `sale/file` и `sale/import` — обратное получение статуса и отмены заказа из 1С.

Доступ защищён отдельными Basic Auth-данными из закрытого `secret/order-config.php`, короткоживущей cookie-сессией, ограничением размера файлов и безопасным XML-парсером без сетевых обращений. Загружаемые XML временно хранятся в плоской папке `secret` и удаляются после импорта.

Остаток хранится в MySQL в `product_inventory`. CommerceML сопоставляет товар по точному SKU `00000050201`; если 1С сначала передаёт каталог, связь внутреннего идентификатора 1С с SKU сохраняется в `onec_product_map`. Поддерживаются общее `Количество`, остатки по складам и элементы `ОстаткиПоСкладу`.

Каждая новая заявка атомарно проверяет доступный остаток и резервирует одну единицу в `inventory_reservations`. При синхронизированном остатке `0` сервер возвращает HTTP 409, даже если блокировку в браузере попытались обойти. До первой выгрузки остатков состояние считается неизвестным и не блокирует существующую форму.

Публичный `stock.php` возвращает актуальный доступный остаток. Форма показывает его рядом с ценой и отключает кнопку при нуле.

## Админка

Закрытая панель доступна по адресу `https://origate-tactic.ru/admin.php`. Она показывает остаток и локальный резерв, позволяет менять цену, создавать, включать, отключать и удалять промокоды, а также просматривать последние 200 заказов в сворачиваемом списке. Цена и промокоды хранятся в MySQL и сразу используются публичной страницей и серверным расчётом новых заказов.

Доступ задаётся в игнорируемом `secret/order-config.php`: в Git хранится только пример с полем `admin.password_hash`. Пароль должен храниться только как bcrypt-хеш. Авторизация использует серверные сессии MySQL, защищённую cookie `Secure`/`HttpOnly`/`SameSite=Strict`, CSRF-токены и ограничение неудачных попыток входа.

Выгрузка реальных заказов в 1С полностью реализована, включая клиента, телефон, email, адрес/ПВЗ, товар, SKU, скидку, доставку отдельной услугой и реквизиты резервирования. Сейчас она заблокирована параметром `one_c.export_orders = false`: `sale/query` возвращает корректный пустой CommerceML-пакет, а новые заказы получают состояние `onec_status=disabled`. После включения флага только новые заказы будут поставлены в очередь. На стороне 1С дополнительно нужно включить автоматическое создание заказа клиента и действие «Резервировать на складе» для заказов с сайта.

Поле `№ товара` намеренно отсутствует. Таблица содержит ровно 15 колонок, заданных в `backend-smoke-test.php`.

Закрытая настройка MySQL и интеграций хранится в `secret/order-config.php` по образцу `order-config.example.php`. Код Google Web App находится в `google-apps-script.example.gs`; рабочая копия с секретом — в игнорируемом Git файле `secret/google-apps-script.gs`. Скрипт разворачивается от владельца таблицы с доступом `Anyone`, а длинный `webhook_secret` защищает запись от посторонних запросов. Саму таблицу можно закрыть для всех и оставить доступ только приглашённым пользователям.

Проверка структуры таблицы, расчёта скидки и доставки, локального резерва, импорта остатков CommerceML, XML-заказа 1С, обоих feature flag, внутренней нумерации и шаблона Telegram выполняется командой `php backend-smoke-test.php`.
