# Воронка Яндекс.Метрики

Счётчик: `112191143`. Все цели отправляются через `ym(..., 'reachGoal', ...)` и одновременно публикуются в браузере как событие `bulldog:funnel`. Персональные данные, адрес, телефон, email и текст комментария в аналитику не передаются.

| Цель | Когда срабатывает | Параметры |
| --- | --- | --- |
| `age_confirmed` | Пользователь подтвердил возраст 18+ | — |
| `age_rejected` | Пользователь отказался подтверждать возраст | — |
| `order_cta_click` | Клик по любой кнопке перехода к форме | `source` |
| `order_form_view` | Форма заказа попала в видимую область | — |
| `order_form_start` | Первое изменение поля формы | — |
| `stock_unavailable` | Продажа заблокирована из-за нулевого или неподтверждённого остатка | `reason` |
| `delivery_calculated` | СДЭК успешно рассчитал доставку | `delivery_type`, `delivery_amount`, `destination` |
| `delivery_error` | Расчёт СДЭК завершился ошибкой | `delivery_type` |
| `order_submit` | Валидная заявка отправлена на сервер | `delivery_type` |
| `order_success` | Сервер создал заказ | `order_price`, `currency`, `delivery_type` |
| `order_error` | Сервер не создал заказ | — |
| `contact_click` | Клик по Email, телефону, Telegram или WhatsApp | `channel` |

Основная конверсионная цепочка: `age_confirmed` → `order_cta_click` → `order_form_view` → `order_form_start` → `delivery_calculated` → `order_submit` → `order_success`.

`order_success` означает оформленный заказ с постоплатой, а не фактическую оплату. Ecommerce-событие `purchase` при оформлении намеренно не отправляется: его следует добавлять только после подтверждённой оплаты или выдачи заказа.

Чтобы цели появились в отчётах Метрики, в настройках счётчика нужно создать цели типа «JavaScript-событие» с идентификаторами из первого столбца таблицы. Для основной воронки достаточно семи целей из конверсионной цепочки; остальные полезны для диагностики потерь.
